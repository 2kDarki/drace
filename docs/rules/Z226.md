# Z226 — Temporal Coupling

## What it targets

Logic that depends on fragile sequencing of nearby assignments.

## Why it exists

When correctness depends on ordering quirks, local edits can create hidden breakage.

## What it encourages

- Explicit state transitions
- Grouped updates with clear intent
- Reduced order-sensitive code paths

## What it does NOT say

- It does not ban sequential code
- It does not claim all nearby assignments are bad
- It highlights coupling risk, not certainty
